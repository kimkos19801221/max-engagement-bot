# MAX API notes

Дата проверки: 2026-08-02.

Источники: портал `business.max.ru` и документация `dev.max.ru`.

## Что важно для проекта

- Используем домен `https://platform-api2.max.ru`.
- Токен передается только через заголовок `Authorization: <token>`.
- Токен нельзя хранить в репозитории, логировать или показывать в ошибках.
- Старый домен `platform-api.max.ru` не используем.
- Для стабильной работы нужно держать общий лимит до 30 rps.
- Для `POST /messages` лимит в один диалог, чат или канал: до 2 сообщений в секунду.

## Получение событий

Production-вариант: webhook.

- Метод настройки: `POST /subscriptions`.
- Endpoint должен быть HTTPS и доступен на 443 порту.
- Сервер должен вернуть HTTP 200 за 30 секунд.
- Нужно передавать `secret` и проверять заголовок `X-Max-Bot-Api-Secret`.
- При ошибках доставки MAX делает повторные попытки.

Разработка и тест: long polling.

- Метод: `GET /updates`.
- Возвращает `updates` и `marker`.
- `marker` нужно сохранять после успешного чтения.
- Если активна webhook-подписка, long polling может не работать.
- Long polling не считаем production-режимом.

## Отправка сообщений

- Метод: `POST /messages`.
- Параметр адресата: `chat_id` или `user_id`.
- Тело: `text`, `attachments`, `link`, `notify`, `format`.
- `text` до 4000 символов.
- `format`: `markdown` или `html`.

## Ограничения до отдельного подтверждения

Без отдельного разрешения нельзя:

- раскрывать или менять реальный токен;
- создавать webhook-подписку;
- отправлять реальные сообщения;
- создавать или менять каналы;
- отключать TLS-проверку при работе с реальным токеном.

Текущий безопасный путь: читать реальные события через `GET /updates`, импортировать историю в локальное хранилище и прогонять worker в dry-run.
